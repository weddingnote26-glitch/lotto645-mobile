# 로또 6/45 분석기 — 모바일 웹앱 (PWA)

기존 Windows 프로그램 **LottoAnalyzer**(`../lotto_analyzer`)의 분석 알고리즘을
그대로 옮겨 담은 **모바일 웹앱**입니다. 앱 설치(APK) 없이 휴대폰 브라우저에서
주소만 열면 바로 쓸 수 있고, 원하면 홈 화면에 추가해 앱처럼 쓸 수 있습니다.

> ⚠️ 이 앱은 과거 데이터를 정리해 보여주는 통계 도구입니다. 로또 추첨은 매회
> 독립적인 무작위 추첨이며, 생성된 번호는 당첨을 예측하거나 보장하지 않습니다.

---

## 1. 기존 PC 프로젝트와의 관계

```
LottoAnalyzer_소스
├── lotto_analyzer      ← 기존 Windows 버전 (읽기 전용 참고. 이번 작업에서 변경 없음)
└── lotto_mobile_web    ← 이 프로젝트 (신규)
```

기존 PC 프로젝트의 파일은 **하나도 수정하지 않았습니다.** 알고리즘을 읽어서
TypeScript로 옮겨 적었을 뿐이고, 두 프로젝트는 서로 아무것도 공유하지 않습니다.

## 2. 로컬 실행

```bash
npm install
```

```bash
npm run dev
```

PC 브라우저에서 <http://localhost:5173> 으로 확인합니다.

**같은 Wi-Fi에 연결된 휴대폰에서 바로 보고 싶을 때**

```bash
npm run dev:lan
```

터미널에 찍히는 `Network: http://192.168.x.x:5173` 주소를 휴대폰 브라우저에
입력하면 됩니다. 처음 실행할 때 Windows 방화벽이 물어보면 "액세스 허용"을
눌러 주세요. (방화벽 설정을 대신 바꾸지는 않습니다.)

> 참고: `http://192.168...` 같은 평문 주소에서는 브라우저가 **복사·공유 기능과
> PWA 설치를 제한**합니다. 앱은 예전 방식으로 자동 대체하지만, 이 기능들까지
> 제대로 확인하려면 아래 5번의 https 배포 주소로 테스트하세요.

## 3. 빌드

```bash
npm run build
```

산출물은 `dist/` 에 생성됩니다. 로컬에서 빌드 결과를 확인하려면:

```bash
npm run preview
```

## 4. 테스트 — PC 버전과 결과가 같은지 검증

```bash
npm test
```

`tests/fixtures/pc_reference.json` 은 **기존 파이썬 코드를 실제로 실행해서**
뽑아낸 기준값입니다. 테스트는 이 값과 모바일 구현의 결과를 항목별로 비교합니다
(최신 회차 · 최근 5회/10회 · 홀짝 · 각 구간 · 1~45 번호별 통계 · 핵심 추천번호 ·
선정 과정 로그). 무작위가 개입하는 부분만 규칙 준수 여부로 검사합니다.

## 5. 배포 (Vercel)

이 프로젝트는 서버가 필요 없는 정적 사이트라 그대로 올리면 됩니다.

1. <https://vercel.com> 에 로그인 → **Add New → Project**
2. 이 폴더(`lotto_mobile_web`)를 올린 저장소를 선택
3. 프로젝트 이름은 **새로** 만듭니다 (예: `lotto645-mobile`).
   기존에 쓰던 다른 Vercel 프로젝트를 절대 고르지 마세요.
4. 설정은 `vercel.json` 에 들어 있어 그대로 두면 됩니다
   (Framework `Vite` · Build `npm run build` · Output `dist`)
5. Deploy → `https://lotto645-mobile.vercel.app` 같은 주소가 나옵니다.

Netlify로 올릴 경우 `netlify.toml` 이 같은 설정을 담고 있습니다.

## 6. 휴대폰에서 사용하기

- 배포된 주소를 휴대폰 브라우저 주소창에 입력하거나, 카카오톡 등으로 링크를
  자신에게 보내 눌러도 됩니다.
- **홈 화면에 추가** (선택 사항)
  - Android Chrome: 우측 상단 ⋮ → "홈 화면에 추가"
  - iPhone Safari: 하단 공유 버튼 → "홈 화면에 추가"
- 추가하지 않고 주소만으로 써도 **모든 기능이 똑같이 동작합니다.**
- 한 번 연 뒤에는 인터넷이 없어도 분석·번호 생성·저장번호 보기가 됩니다.

## 7. 당첨번호 데이터 업데이트

앱에는 제1~1236회 데이터가 내장되어 있습니다. 새 회차가 나오면:

1. 동행복권에서 "회차별 당첨번호" 엑셀(.xlsx)을 내려받습니다.
2. 앱 하단 **설정** 탭 → **[당첨번호 데이터 업데이트]**
3. 휴대폰 파일 선택창에서 그 엑셀을 고릅니다.

선택한 파일은 **휴대폰 브라우저 안에서만** 읽습니다. 어떤 서버로도 올라가지
않습니다. 읽은 데이터는 브라우저(IndexedDB)에 저장되어 앱을 껐다 켜도 유지되고,
분석은 자동으로 다시 계산됩니다. 언제든 [내장 기본 데이터로 되돌리기]로
원래대로 돌릴 수 있습니다.

엑셀은 **회차 열 + 당첨번호 6개 열**만 있으면 됩니다. 열 이름이 조금 달라도
(`번호1`, `ball1`, `1번`, 병합된 `당첨번호` 등) 자동으로 찾아냅니다. 보너스
번호는 형식만 검사하고 **분석에서는 제외**합니다 (PC 버전과 동일).

## 8. 분석·추천 알고리즘

PC 버전 `core/number_selector.py` 의 **1~9순위 순차 필터**를 그대로 옮겼습니다.
임의 가중치 점수로 바꾸지 않았고, 순서와 판정 기준이 코드에 고정되어 있습니다.

1. 최근 5회 출현 횟수 최다
2. 최근 10회 출현 횟수 최다
3·4. 10단위 구간(1~10/11~20/21~30/31~40/41~45) — **구간 크기 보정** 출현률이
   가장 낮은 구간 우선 (41~45는 숫자가 5개뿐이라 보정이 꼭 필요)
5. 15단위 구간(1~15/16~30/31~45) 출현 비율 최저 구간 우선
6. 최근 10회에서 적게 나온 홀/짝 쪽 우선 (동수면 통과)
7. 직전 회차 미출현 + 최근 5회 안에 1회 이상 출현
8. 미출현 간격 1~3회
9. 위 8단계로도 완전 동률이면 그때만 무작위 선택 — 화면에 그 사실을 표시

각 필터는 후보를 좁히지 못하면 후보를 그대로 통과시키고, 후보가 1개가 되는
순간 확정합니다. 홈 화면의 **[왜 이 번호인가요?]** 에서 단계별로 어떻게
좁혀졌는지 볼 수 있습니다.

번호 생성은 두 가지입니다.

- **완전 랜덤** — 1~45에서 중복 없이 6개
- **분석 기반 균형 추첨** (권장) — 홀짝 2:4~4:2(3:3 우선), 10단위 구간 3개 이상,
  15단위 구간 각 1개 이상, 연속번호 1쌍 이하가 되도록 **쏠림만 줄입니다.**
  당첨 확률을 높이는 규칙이 아닙니다.

## 9. 개인정보 · 권한

- 로그인·회원가입·서버·DB가 **없습니다.** 모든 계산은 브라우저 안에서 합니다.
- 위치·카메라·마이크·연락처 권한을 쓰지 않습니다.
- 사용자가 직접 고른 엑셀 파일만 읽습니다.

## 11. 참고 — SheetJS 설치 경로

엑셀 파싱에 쓰는 `xlsx`(SheetJS)는 **npm 레지스트리 버전이 0.18.5에서 멈춰 있고
알려진 보안 권고(프로토타입 오염·ReDoS)가 해결되지 않았습니다.** 그래서 SheetJS
공식 배포처에서 패치된 0.20.3을 설치하도록 `package.json` 에 적어 두었습니다.

```
"xlsx": "https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz"
```

`npm audit` 기준 취약점 0건입니다. 설치·빌드 시 `cdn.sheetjs.com` 에 접근할 수
있어야 하며, 이는 SheetJS가 공식적으로 안내하는 설치 방법입니다.
